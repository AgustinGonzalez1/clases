# Clase 27: Checkpoints y Vidas ❤️

Al morir reaparecés en el último checkpoint que tocaste. Tenés 3 vidas, que se ven como corazones; si las perdés todas, volvés al inicio.

## Objetivos

- Usar SpawnLocations como checkpoints con `RespawnLocation`
- Contar las vidas con `Humanoid.Died` y atributos
- Mostrar las vidas como corazones con `string.rep`

## Contenido

### 🚩 Parte 1: Checkpoints

Una **SpawnLocation** es una Part que marca dónde aparece el jugador. Cada jugador tiene la propiedad `RespawnLocation`, que dice en cuál reaparece al morir:

```lua
jugador.RespawnLocation = workspace.Checkpoints["2"]  -- la proxima vez aparece en el checkpoint 2
```

Ese es todo el truco: cuando toca un checkpoint, cambiamos su `RespawnLocation`.

### Paso 1: El inicio

Seleccionás la **SpawnLocation** que trae la plantilla y la renombrás `Inicio`. Tiene, además de las de cualquier Part, estas propiedades propias:

| Propiedad | Sección | Valor | Para qué sirve |
|---|---|---|---|
| **Duration** ✏️ | Campo de fuerza | `0` | Segundos de escudo (ForceField) al aparecer. En un obby no hace falta |
| **Neutral** ✏️ | Equipos | `true` | Cualquier jugador puede aparecer acá, no solo un equipo |
| **TeamColor** | Equipos | — | El equipo que aparece acá; solo cuenta si **Neutral** está en `false` |
| **AllowTeamChangeOnTouch** | Equipos | ✗ | Si al tocarla te cambia de equipo |

*✏️ = las que cambiamos. Las de equipos se usan cuando hay equipos; acá no.*

### Paso 2: Los checkpoints

1. Click derecho en **Workspace** → Insert Object (**Insertar objeto**) → **Folder**, la renombrás `Checkpoints`
2. Click derecho en `Checkpoints` → Insert Object (**Insertar objeto**) → **SpawnLocation**, la renombrás `1`
3. Igual que el `Inicio`: **Duration** en `0` y **Neutral** en `true`. Además, **Color** verde para que se note que es un checkpoint
4. Repetís para el `2` y el `3`, y los ponés en orden a lo largo del obby

![Propiedades del checkpoint](roblox/img/clase27/01-propiedades-checkpoint.png)
*Así se ven en Propiedades: **Duration** en **Campo de fuerza** y **Neutral** en **Equipos**.*

> ⚠️ Los nombres tienen que ser **números** (`1`, `2`, `3`): el script los usa para saber cuál está más adelante.

### Paso 3: El bloque de la muerte

Para probar. Una **Part** en Workspace llamada `BloqueMuerte`, después del checkpoint `1`:

| Propiedad | Valor | Para qué sirve |
|---|---|---|
| **Color** | Rojo | Que se note que es peligroso |
| **Anchored** | `true` | Que no se mueva |

Adentro, un **Script** (el de la Clase 7). Cuando lo toca un personaje, le pone la vida (`Health`) en 0:

```lua
-- Referencias
local bloque = script.Parent                        -- el bloque que contiene este script

-- Funciones
local function alTocar(parteQueToco)
    local humanoid = parteQueToco.Parent:FindFirstChild("Humanoid")  -- busca si lo toco un personaje
    if humanoid then                                -- si fue un personaje
        humanoid.Health = 0                         -- lo mata
    end
end

-- Inicio
bloque.Touched:Connect(alTocar)                     -- cuando algo toca el bloque
```

*El `Inicio`, los checkpoints `1`, `2` y `3` en verde, y el `BloqueMuerte` en rojo.*

### Paso 4: El script Checkpoints

Click derecho en **ServerScriptService** → Insert Object (**Insertar objeto**) → **Script**, lo renombrás `Checkpoints`:

```lua
-- Servicios
local Players = game:GetService("Players")          -- servicio que maneja a los jugadores

-- Referencias
local inicio = workspace:WaitForChild("Inicio")     -- la SpawnLocation donde arranca todo
local carpetaCheckpoints = workspace:WaitForChild("Checkpoints")  -- la carpeta con los checkpoints

-- Funciones
local function numeroDeCheckpoint(spawn)
    return tonumber(spawn.Name) or 0                -- convierte el nombre en numero; Inicio no es numero, da 0
end

local function alTocarCheckpoint(checkpoint, parteQueToco)
    local jugador = Players:GetPlayerFromCharacter(parteQueToco.Parent)  -- busca que jugador lo toco
    if not jugador then return end                  -- si no fue un jugador, no hace nada

    local numeroActual = numeroDeCheckpoint(jugador.RespawnLocation)  -- en que checkpoint esta ahora
    local numeroNuevo = numeroDeCheckpoint(checkpoint)                -- que checkpoint toco

    if numeroNuevo > numeroActual then              -- solo si esta mas adelante
        jugador.RespawnLocation = checkpoint        -- la proxima vez reaparece aca
    end
end

local function alEntrarJugador(jugador)
    jugador.RespawnLocation = inicio                -- todos arrancan en el inicio
end

-- Inicio
for _, checkpoint in carpetaCheckpoints:GetChildren() do          -- recorre todos los checkpoints
    checkpoint.Touched:Connect(function(parteQueToco)             -- cuando algo toca este checkpoint
        alTocarCheckpoint(checkpoint, parteQueToco)
    end)
end

for _, jugador in Players:GetPlayers() do           -- jugadores que ya estaban antes de que corra el script
    alEntrarJugador(jugador)
end

Players.PlayerAdded:Connect(alEntrarJugador)        -- jugadores que entren despues
```

- `Touched` avisa cuando alguien pisa un checkpoint, y ahí se cambia su `RespawnLocation`
- `tonumber(spawn.Name)` convierte `"2"` en `2`. `"Inicio"` no es un número, así que con el `or 0` vale `0`
- El checkpoint **solo avanza**: si estás en el 3 y pisás el 1, no retrocedés
- `alEntrarJugador` pone a todos en `Inicio`; sin esto, Roblox podría hacerlos aparecer en cualquier checkpoint
- El `for` recorre la carpeta (Clase 21): si agregás un checkpoint `4`, funciona solo

**Probalo:** Play, pasá por el `1` y pisá el bloque rojo: reaparecés en el `1`.

### ❤️ Parte 2: Vidas

Las vidas se guardan en un **atributo** del jugador. Si el servidor lo cambia, el cliente se entera solo, sin RemoteEvent:

```lua
jugador:SetAttribute("Vidas", 3)            -- le guarda el atributo Vidas con el valor 3
print(jugador:GetAttribute("Vidas"))        -- imprime: 3
```

### Paso 1: El texto de las vidas

1. Click derecho en **StarterGui** → **ScreenGui**, la renombrás `VidasGui`
2. Adentro, un **TextLabel** llamado `TextoVidas`:

> 📝 **Qué es un ScreenGui:** la "capa" donde va todo lo que se dibuja en pantalla. Lo que pongas en **StarterGui** se le copia a cada jugador al entrar.

| Propiedad | Valor | Para qué sirve |
|---|---|---|
| **Size** | `{0.2, 0}, {0.08, 0}` | 20% del ancho y 8% del alto de la pantalla |
| **Position** | `{0.02, 0}, {0.02, 0}` | Arriba a la izquierda, con un pequeño margen |
| **TextScaled** | `true` | Los corazones se ajustan al tamaño del recuadro |
| **BackgroundTransparency** | `1` | Sin fondo, solo los corazones |
| **TextXAlignment** | `Left` | Pegados a la izquierda: al perder una vida, se va el de la derecha |
| **Text** | `...` | Lo que se ve hasta que llegan las vidas del servidor |

### Paso 2: El LocalScript

Para repetir el corazón se usa `string.rep`:

```lua
print(string.rep("❤️", 3))    -- imprime: ❤️❤️❤️
print(string.rep("⭐", 5))    -- imprime: ⭐⭐⭐⭐⭐
```

> ⚠️ En Lua **no** se puede hacer `"❤️" * 3`: tira error. Eso es de Python.

Click derecho en `TextoVidas` → Insert Object (**Insertar objeto**) → **LocalScript**:

```lua
-- Servicios
local Players = game:GetService("Players")          -- servicio que maneja a los jugadores

-- Referencias
local jugador = Players.LocalPlayer                 -- el jugador que ve esta pantalla
local texto = script.Parent                         -- el TextLabel que contiene este script

-- Funciones
local function actualizarTexto()
    local vidas = jugador:GetAttribute("Vidas")     -- lee las vidas

    if vidas then                                   -- si ya llegaron del servidor
        texto.Text = string.rep("❤️", vidas)        -- repite el corazon tantas veces como vidas tenga
    else
        texto.Text = "..."                          -- si todavia no llegaron, muestra ...
    end
end

-- Inicio
actualizarTexto()                                   -- muestra las vidas apenas arranca
jugador:GetAttributeChangedSignal("Vidas"):Connect(actualizarTexto)  -- y cada vez que cambian
```

- **No calcula nada**: solo muestra el atributo `Vidas` que guarda el servidor
- `string.rep("❤️", vidas)` repite el corazón: con 3 vidas muestra ❤️❤️❤️
- `GetAttributeChangedSignal` avisa cada vez que cambian las vidas
- El `if vidas then` cubre el primer instante, cuando el atributo todavía no llegó

### Paso 3: El script Vidas

Click derecho en **ServerScriptService** → Insert Object (**Insertar objeto**) → **Script**, lo renombrás `Vidas`:

```lua
-- Servicios
local Players = game:GetService("Players")          -- servicio que maneja a los jugadores

-- Configuracion
local VIDAS_INICIALES = 3                           -- con cuantas vidas arranca cada jugador

-- Referencias
local inicio = workspace:WaitForChild("Inicio")     -- la SpawnLocation donde arranca todo

-- Funciones
local function alMorir(jugador)
    local vidas = jugador:GetAttribute("Vidas") - 1 -- le resta una vida

    if vidas <= 0 then                              -- si se quedo sin vidas
        jugador.RespawnLocation = inicio            -- pierde los checkpoints, vuelve al inicio
        vidas = VIDAS_INICIALES                     -- y recupera todas las vidas
    end

    jugador:SetAttribute("Vidas", vidas)            -- guarda las vidas nuevas (el cliente se entera solo)
end

local function alAparecerPersonaje(jugador, personaje)
    local humanoid = personaje:WaitForChild("Humanoid")  -- espera a que el Humanoid este listo
    humanoid.Died:Connect(function()                -- cuando este personaje muere
        alMorir(jugador)
    end)
end

local function alEntrarJugador(jugador)
    jugador:SetAttribute("Vidas", VIDAS_INICIALES)  -- arranca con todas las vidas

    jugador.CharacterAdded:Connect(function(personaje)  -- cada vez que aparece o reaparece
        alAparecerPersonaje(jugador, personaje)
    end)

    if jugador.Character then                       -- si el personaje ya habia aparecido
        alAparecerPersonaje(jugador, jugador.Character)
    end
end

-- Inicio
for _, jugador in Players:GetPlayers() do           -- jugadores que ya estaban antes de que corra el script
    alEntrarJugador(jugador)
end

Players.PlayerAdded:Connect(alEntrarJugador)        -- jugadores que entren despues
```

- `SetAttribute("Vidas", 3)` le da las vidas al entrar
- `humanoid.Died` avisa cuando el personaje muere; le resta una vida
- Con 0 vidas: vuelve a `Inicio` y recupera las 3
- Al reaparecer hay un **Humanoid nuevo**: por eso `CharacterAdded` vuelve a conectar el `Died`

> ⚠️ `SetAttribute` y `GetAttribute` van con **dos t**. Con `SetAtribute` las vidas nunca se guardan y los corazones no cambian.

### Problemas comunes

| Problema | Solución |
|---|---|
| Al empezar aparezco en cualquier checkpoint | La SpawnLocation de inicio tiene que llamarse `Inicio` |
| Reaparezco en el inicio aunque toqué un checkpoint | Los checkpoints se llaman `1`, `2`, `3` y están dentro de `Checkpoints` |
| Los corazones no cambian al morir | Revisá que diga `SetAttribute`, con dos t (mirá el Output) |
| Se queda en `...` | Falta el script `Vidas` en ServerScriptService |
| Aparece un escudo brillante | **Duration** en `0` en todas las SpawnLocations |
