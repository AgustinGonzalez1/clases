# Clase 27: Checkpoints y Vidas ❤️

Hacemos que el jugador reaparezca en el último checkpoint que tocó, y le agregamos un contador de vidas que se muestra en pantalla con corazones.

## Objetivos

- Usar SpawnLocations como checkpoints
- Cambiar dónde reaparece un jugador con `RespawnLocation`
- Detectar cuándo muere un jugador con `Humanoid.Died`
- Usar Attributes (atributos) para compartir datos del servidor con el cliente sin RemoteEvents
- Repetir texto con `string.rep` para mostrar las vidas como corazones

## Contenido

### 1. ¿Qué es una SpawnLocation?

Una **SpawnLocation** es una Part especial que marca **dónde aparece el jugador**. La plantilla Baseplate ya trae una. Si hay varias, Roblox puede usar cualquiera de ellas.

| Propiedad | Qué hace | Valor para el obby |
|---|---|---|
| **Neutral** | Si está en `true`, sirve para cualquier jugador. Si está en `false`, solo para un equipo | `true` |
| **Duration** | Segundos de escudo protector (ForceField) al aparecer | `0` |
| **Enabled** | Si se puede usar para aparecer | `true` |
| **Anchored** | Que no se caiga | `true` |

> 💡 `Duration` en `0` saca el escudo brillante que aparece alrededor del personaje al reaparecer, que en un obby no hace falta.

### 2. ¿Qué es RespawnLocation?

Cada jugador tiene una propiedad `RespawnLocation`: indica en **qué SpawnLocation va a reaparecer** la próxima vez que muera.

```lua
jugador.RespawnLocation = workspace.Checkpoints["2"]  -- la proxima vez aparece en el checkpoint 2
```

Ese es todo el truco de los checkpoints: cuando el jugador toca uno, cambiamos su `RespawnLocation` a ese checkpoint.

### 3. ¿Qué son los Attributes?

Un **Attribute** (atributo) es un dato con nombre que se le puede pegar a cualquier objeto de Roblox, como una etiqueta con un valor:

```lua
jugador:SetAttribute("Vidas", 3)            -- le guarda el atributo Vidas con el valor 3
print(jugador:GetAttribute("Vidas"))        -- imprime: 3
```

Lo importante: si el **servidor** le pone un atributo a un jugador, ese atributo **viaja solo al cliente**. Así el cliente puede mostrar las vidas en pantalla **sin necesitar un RemoteEvent** (Clase 23).

| Función | Qué hace |
|---|---|
| `SetAttribute("Nombre", valor)` | Guarda o cambia el atributo |
| `GetAttribute("Nombre")` | Lee el valor actual |
| `GetAttributeChangedSignal("Nombre")` | Evento que avisa cada vez que ese atributo cambia |

> 💡 Mientras jugás en Studio, si seleccionás tu jugador en **Players**, vas a ver el atributo `Vidas` en el panel Properties, en la sección **Atributos**. Sirve mucho para revisar que todo funcione.

### 4. Repetir texto con string.rep

Para mostrar las vidas como corazones (❤️❤️❤️) necesitamos repetir un texto varias veces. En Lua eso se hace con `string.rep(texto, cantidad)`:

```lua
print(string.rep("❤️", 3))    -- imprime: ❤️❤️❤️
print(string.rep("⭐", 5))    -- imprime: ⭐⭐⭐⭐⭐
```

> ⚠️ En Lua **no** se puede hacer `"❤️" * 3`. El `*` es solo para multiplicar números y tira error (`attempt to perform arithmetic on a string value`). Esa forma de repetir texto existe en otros lenguajes como Python, pero no en Lua.

### 5. Cómo vamos a organizar los scripts

Igual que en la Clase 26, un script por tarea, todos con el mismo orden interno (Servicios → Configuración → Referencias → Funciones → Inicio):

| Script | Dónde va | Qué hace |
|---|---|---|
| `Checkpoints` | ServerScriptService | Cambia el punto de reaparición al tocar un checkpoint |
| `Vidas` | ServerScriptService | Resta vidas al morir y te manda al inicio si llegan a 0 |
| LocalScript | Dentro de `TextoVidas` | Muestra las vidas en pantalla como corazones |
| Script | Dentro de `BloqueMuerte` | Mata al jugador al tocarlo (para probar) |

### 🚩 Parte 1: Checkpoints

### 6. Preparar la SpawnLocation de inicio

1. En el Workspace, seleccionás la **SpawnLocation** que trae la plantilla
2. La renombrás `Inicio`
3. En Properties: **Neutral** en `true`, **Duration** en `0`

### 7. Crear los checkpoints

1. Click derecho en **Workspace** → Insert Object → **Folder**, la renombrás `Checkpoints`
2. Click derecho en `Checkpoints` → Insert Object → **SpawnLocation**
3. La renombrás `1`
4. En Properties: **Neutral** en `true`, **Duration** en `0`, y un color llamativo (por ejemplo verde)
5. Repetís para crear `2` y `3`
6. Los ubicás a lo largo del obby, en orden: el `1` después del primer tramo, el `2` en el medio, el `3` cerca del final

```
Workspace
  ├── Inicio (SpawnLocation)
  └── Checkpoints (Folder)
        ├── 1 (SpawnLocation)
        ├── 2 (SpawnLocation)
        └── 3 (SpawnLocation)
```

> ⚠️ Los nombres tienen que ser **números** (`1`, `2`, `3`). El script usa ese número para saber qué checkpoint está más adelante.

### 8. El script Checkpoints

1. Click derecho en **ServerScriptService** → Insert Object → **Script**
2. Lo renombrás `Checkpoints`

```lua
-- Servicios
local Players = game:GetService("Players")          -- servicio que maneja a los jugadores

-- Referencias
local inicio = workspace:WaitForChild("Inicio")     -- la SpawnLocation donde arranca todo
local carpetaCheckpoints = workspace:WaitForChild("Checkpoints")  -- la carpeta con los checkpoints

-- Funciones
local function numeroDeCheckpoint(spawn)
    return tonumber(spawn.Name) or 0                -- convierte el nombre en numero; Inicio no es numero, da 0
end

local function alTocarCheckpoint(checkpoint, parteQueToco)
    local jugador = Players:GetPlayerFromCharacter(parteQueToco.Parent)  -- busca que jugador lo toco
    if not jugador then return end                  -- si no fue un jugador, no hace nada

    local numeroActual = numeroDeCheckpoint(jugador.RespawnLocation)  -- en que checkpoint esta ahora
    local numeroNuevo = numeroDeCheckpoint(checkpoint)                -- que checkpoint toco

    if numeroNuevo > numeroActual then              -- solo si esta mas adelante
        jugador.RespawnLocation = checkpoint        -- la proxima vez reaparece aca
    end
end

local function alEntrarJugador(jugador)
    jugador.RespawnLocation = inicio                -- todos arrancan en el inicio
end

-- Inicio
for _, checkpoint in ipairs(carpetaCheckpoints:GetChildren()) do  -- recorre todos los checkpoints
    checkpoint.Touched:Connect(function(parteQueToco)             -- cuando algo toca este checkpoint
        alTocarCheckpoint(checkpoint, parteQueToco)
    end)
end

for _, jugador in ipairs(Players:GetPlayers()) do   -- jugadores que ya estaban antes de que corra el script
    alEntrarJugador(jugador)
end

Players.PlayerAdded:Connect(alEntrarJugador)        -- jugadores que entren despues
```

- `GetPlayerFromCharacter(parteQueToco.Parent)` recibe el personaje y devuelve el jugador. Si lo que tocó no es un personaje (una pelota, otra Part), devuelve `nil`
- `tonumber(spawn.Name)` convierte el nombre `"2"` en el número `2`. Como `"Inicio"` no es un número, devuelve `nil`, y el `or 0` lo transforma en `0`
- `alEntrarJugador` pone el inicio apenas entra el jugador. Sin esto, como hay varias SpawnLocations, Roblox podría hacerlo aparecer **al azar en cualquier checkpoint**
- El `for` recorre la carpeta (Clases 20 y 21), así si mañana agregás un checkpoint `4`, funciona solo, sin tocar el código

### 9. Por qué los checkpoints solo avanzan

Sin el `if numeroNuevo > numeroActual`, si el jugador está en el checkpoint 3 y por error pisa el 1, volvería a reaparecer en el 1 y perdería su progreso.

| Está en | Toca | ¿Cambia? |
|---|---|---|
| Inicio (0) | 1 | ✅ Sí, 1 es mayor que 0 |
| 1 | 2 | ✅ Sí |
| 3 | 1 | ❌ No, 1 es menor que 3 |
| 2 | 2 | ❌ No, es el mismo |

Además, esto resuelve otro problema: `Touched` se dispara **por cada parte del cuerpo** que toca el checkpoint. Como después del primer toque ya no es "más adelante", los toques repetidos no hacen nada.

### 10. Crear el texto de las vidas

1. Click derecho en **StarterGui** → Insert Object → **ScreenGui**, la renombrás `VidasGui`
2. Click derecho en `VidasGui` → Insert Object → **TextLabel**, lo renombrás `TextoVidas`
3. Configurás sus propiedades:

| Propiedad | Valor |
|---|---|
| **Size** | `{0.2, 0}, {0.08, 0}` |
| **Position** | `{0.02, 0}, {0.02, 0}` |
| **TextScaled** | `true` |
| **BackgroundTransparency** | `1` |
| **TextXAlignment** | `Left` |
| **Text** | `...` |

4. Click derecho en `TextoVidas` → Insert Object → **LocalScript**

```
StarterGui
  └── VidasGui (ScreenGui)
        └── TextoVidas (TextLabel)
              └── LocalScript
```

> 💡 `TextXAlignment` en `Left` hace que los corazones queden pegados a la izquierda. Así, cuando perdés una vida, el corazón que desaparece es el de la derecha, como en los videojuegos.

### 11. El código del texto (LocalScript dentro de TextoVidas)

```lua
-- Servicios
local Players = game:GetService("Players")          -- servicio que maneja a los jugadores

-- Referencias
local jugador = Players.LocalPlayer                 -- el jugador que ve esta pantalla
local texto = script.Parent                         -- el TextLabel que contiene este script

-- Funciones
local function actualizarTexto()
    local vidas = jugador:GetAttribute("Vidas")     -- lee las vidas

    if vidas then                                   -- si ya llegaron del servidor
        texto.Text = string.rep("❤️", vidas)        -- repite el corazon tantas veces como vidas tenga
    else
        texto.Text = "..."                          -- si todavia no llegaron, muestra ...
    end
end

-- Inicio
actualizarTexto()                                   -- muestra las vidas apenas arranca
jugador:GetAttributeChangedSignal("Vidas"):Connect(actualizarTexto)  -- y cada vez que cambian
```

- Este script **no calcula nada**: solo muestra lo que el servidor guardó en el atributo `Vidas`
- `string.rep("❤️", vidas)` repite el corazón: con 3 vidas muestra ❤️❤️❤️, con 2 muestra ❤️❤️
- `GetAttributeChangedSignal("Vidas")` avisa cada vez que el servidor cambia las vidas, así los corazones se actualizan solos
- El `if vidas then` cubre el primer instante del juego, cuando el atributo todavía no llegó del servidor. Sin ese control, `string.rep` recibiría `nil` como cantidad y tiraría error

### 12. El script Vidas

1. Click derecho en **ServerScriptService** → Insert Object → **Script**
2. Lo renombrás `Vidas`

```lua
-- Servicios
local Players = game:GetService("Players")          -- servicio que maneja a los jugadores

-- Configuracion
local VIDAS_INICIALES = 3                           -- con cuantas vidas arranca cada jugador

-- Referencias
local inicio = workspace:WaitForChild("Inicio")     -- la SpawnLocation donde arranca todo

-- Funciones
local function alMorir(jugador)
    local vidas = jugador:GetAttribute("Vidas") - 1 -- le resta una vida

    if vidas <= 0 then                              -- si se quedo sin vidas
        jugador.RespawnLocation = inicio            -- pierde los checkpoints, vuelve al inicio
        vidas = VIDAS_INICIALES                     -- y recupera todas las vidas
    end

    jugador:SetAttribute("Vidas", vidas)            -- guarda las vidas nuevas (el cliente se entera solo)
end

local function alAparecerPersonaje(jugador, personaje)
    local humanoid = personaje:WaitForChild("Humanoid")  -- espera a que el Humanoid este listo
    humanoid.Died:Connect(function()                -- cuando este personaje muere
        alMorir(jugador)
    end)
end

local function alEntrarJugador(jugador)
    jugador:SetAttribute("Vidas", VIDAS_INICIALES)  -- arranca con todas las vidas

    jugador.CharacterAdded:Connect(function(personaje)  -- cada vez que aparece o reaparece
        alAparecerPersonaje(jugador, personaje)
    end)

    if jugador.Character then                       -- si el personaje ya habia aparecido
        alAparecerPersonaje(jugador, jugador.Character)
    end
end

-- Inicio
for _, jugador in ipairs(Players:GetPlayers()) do   -- jugadores que ya estaban antes de que corra el script
    alEntrarJugador(jugador)
end

Players.PlayerAdded:Connect(alEntrarJugador)        -- jugadores que entren despues
```

- `humanoid.Died` es un evento que se dispara cuando la vida del personaje llega a 0
- Cada vez que el jugador reaparece, Roblox crea un **personaje nuevo** con un **Humanoid nuevo**. Por eso `CharacterAdded` vuelve a conectar el `Died` en cada reaparición
- El `if jugador.Character` cubre el caso de que el personaje ya haya aparecido antes de que el script conectara `CharacterAdded`
- Cambiar `RespawnLocation` dentro de `alMorir` funciona porque el jugador tarda unos segundos en reaparecer, y para ese momento ya sabe que tiene que volver al inicio

### 13. Crear un bloque de la muerte para probar

Reutilizamos el bloque de la Clase 7:

1. Insertás una **Part** en el Workspace, la renombrás `BloqueMuerte` y la pintás de rojo
2. **Anchored** en `true`
3. Click derecho en la Part → Insert Object → **Script**

```lua
-- Referencias
local bloque = script.Parent                        -- el bloque que contiene este script

-- Funciones
local function alTocar(parteQueToco)
    local humanoid = parteQueToco.Parent:FindFirstChild("Humanoid")  -- busca si lo toco un personaje
    if humanoid then                                -- si fue un personaje
        humanoid.Health = 0                         -- lo mata
    end
end

-- Inicio
bloque.Touched:Connect(alTocar)                     -- cuando algo toca el bloque
```

Lo ubicás **después** de algún checkpoint, así podés probar que reaparecés ahí.

### 14. Probar todo

1. Le das **Play** en Studio
2. Revisás que arriba a la izquierda aparezcan **❤️❤️❤️** y que arranques en `Inicio`
3. Tocás el checkpoint `1` y después el `BloqueMuerte`: tenés que reaparecer en el `1` con **❤️❤️**
4. Avanzás hasta el `2`, volvés a tocar el `1`, y morís: tenés que reaparecer en el `2` (no retrocede) con **❤️**
5. Morís una vez más: al llegar a 0 volvés a `Inicio` con **❤️❤️❤️**
6. Si algo no anda, seleccioná tu jugador en **Players** y mirá el atributo `Vidas` en Properties
