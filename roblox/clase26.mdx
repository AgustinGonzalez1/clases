# Clase 26: ¡A Ganar Robux! (Monetización) 💰

Aprendemos a vender cosas dentro de nuestro juego con Robux, y a entregar lo comprado de forma segura desde el servidor. La clase se divide en dos partes: primero el **Pase** y después el **Producto del desarrollador**.

## Objetivos

- Entender la diferencia entre Pases y Productos del desarrollador, y cuándo usar cada uno
- Publicar el juego y crear un Pase y un Producto desde el Creator Dashboard
- Vender un Pase que entrega un ítem permanente
- Vender un Producto del desarrollador que da un boost temporal y se puede comprar varias veces
- Organizar el código en scripts chicos, con una estructura clara y repetible

## Contenido

### 1. Las dos formas de vender en Roblox

| | Pase (Game Pass) | Producto del desarrollador (Developer Product) |
|---|---|---|
| Se puede comprar | **Una sola vez** por jugador | **Todas las veces que quiera** |
| ¿Roblox recuerda la compra? | **Sí**, para siempre | **No**, solo registra que pagó |
| Cómo se entrega | Verificando con `UserOwnsGamePassAsync` | Con `ProcessReceipt` (recibo de compra) |
| Precio mínimo | No puede ser 0 | No puede ser 0 |

**Cuándo usar cada uno:**

| Usar Pase para... | Usar Producto del desarrollador para... |
|---|---|
| Un arma o herramienta permanente | Velocidad extra por 10 minutos |
| Acceso VIP (Very Important Person, zona exclusiva) | Curarse la vida completa |
| Multiplicador permanente de XP (puntos de experiencia) | Revivir después de morir |
| Un cosmético para siempre | Moneda del juego (se ve en la Clase 30) |

> ⚠️ **El error más común**: vender algo repetible como Pase. Si hacés la velocidad extra como Pase, el jugador la tiene **para siempre** y rompe el balance del juego.

### 2. Publicar el juego

Los Pases y Productos se crean **asociados a un juego publicado**. Si el juego no está publicado, no aparece en el Dashboard.

1. En Studio: **Archivo** → **Publicar en Roblox**
2. Elegís **crear una experiencia nueva**
3. Le ponés nombre y descripción
4. Click en **Crear**

El juego queda publicado en modo **Privado**: nadie más lo puede jugar, pero ya podés venderle cosas.

### 3. ¿Cómo se comunican los botones y el servidor?

**El LocalScript no le avisa nada al servidor**: Roblox se encarga de avisarle a ambos lados cuando se procesa una compra.

```
LocalScript (cliente)                    Script (servidor)
     |                                          |
Jugador toca el boton                           |
     |                                          |
Prompt...Purchase() ---------> Roblox muestra su dialogo de pago
                                                 |
                                 Roblox procesa el pago
                                                 |
                              Roblox le avisa al servidor
```

> 🔒 **Regla de oro**: el cliente solo se encarga de lo **visual** (el botón). La decisión de entregar algo **siempre** la toma el servidor.

### 4. Cómo vamos a organizar los scripts

Vamos a tener **4 scripts chicos**, cada uno con **una sola tarea**:

| Script | Dónde va | Qué hace |
|---|---|---|
| LocalScript | Dentro del botón `ComprarPase` | Muestra el precio y abre la compra del Pase |
| `PaseLinterna` | ServerScriptService | Entrega la Linterna a quien compró el Pase |
| LocalScript | Dentro del botón `ComprarVelocidad` | Muestra el precio y abre la compra del Producto |
| `ProductosDesarrollador` | ServerScriptService | Da la velocidad extra cuando alguien la compra |

Y todos siguen **el mismo orden interno**, así cualquier script se lee igual:

```lua
-- Servicios        → los game:GetService que usa el script
-- Configuracion    → IDs y valores que se pueden cambiar
-- Referencias      → objetos del juego que usa (botones, items)
-- Funciones        → cada tarea en una funcion con nombre claro
-- Inicio           → lo que se ejecuta y se conecta al arrancar
```

> 💡 Si algo falla con la velocidad, sabés que el problema está en `ProductosDesarrollador` y no tenés que buscar entre 100 líneas mezcladas.

### 🎟️ Parte 1: El Pase (compra única)

Vamos a vender una **Linterna Premium**: el jugador la compra una vez y la tiene para siempre.

### 5. Crear el Pase en el Dashboard

1. Entrás a **create.roblox.com/dashboard/creations**
2. Seleccionás tu juego
3. Menú lateral: **Monetización** → **Pases**
4. Click en el botón azul **"Crear Pase"**
5. Le ponés nombre ("Linterna Premium"), descripción e ícono (512x512)
6. Guardás
7. Entrás al Pase creado, a la configuración de **ventas**, lo ponés **a la venta** y le asignás un precio en Robux
8. Copiás el **ID (identificador)** del Pase, desde el menú de los tres puntos (⋯) o desde la dirección del navegador

> ⚠️ Si no lo ponés a la venta, el botón del juego va a decir "No disponible".

### 6. Crear la Linterna (el ítem premium)

1. Click derecho en **ServerStorage** → Insert Object → **Tool**, lo renombrás `Linterna`
2. Click derecho en la Tool → Insert Object → **Part**, la renombrás `Handle` (nombre obligatorio, es de donde la agarra el personaje, como en la Clase 11)
3. Achicás la Part para que tenga forma de linterna (por ejemplo `Size: 0.5, 0.5, 2`)
4. Click derecho en `Handle` → Insert Object → **SpotLight**, así la linterna ilumina de verdad
5. En el SpotLight: **Brightness** en `5` y **Range** en `30`

```
ServerStorage
  └── Linterna (Tool)
        └── Handle (Part)
              └── SpotLight
```

> 💡 Va en **ServerStorage** y no en StarterPack, porque no queremos que nadie la tenga hasta que el servidor se la dé.

### 7. Crear el botón del Pase

1. Click derecho en **StarterGui** → Insert Object → **ScreenGui**, la renombrás `TiendaGui`
2. Click derecho en `TiendaGui` → Insert Object → **TextButton**, lo renombrás `ComprarPase`
3. Configurás sus propiedades:

| Propiedad | Valor |
|---|---|
| **Size** | `{0.2, 0}, {0.08, 0}` |
| **Position** | `{0.02, 0}, {0.8, 0}` |
| **TextScaled** | `true` |
| **Text** | `Cargando...` |

4. Click derecho en `ComprarPase` → Insert Object → **LocalScript**

```
StarterGui
  └── TiendaGui (ScreenGui)
        └── ComprarPase (TextButton)
              └── LocalScript
```

> 💡 El LocalScript va **dentro** del botón, así `script.Parent` es directamente el botón, sin tener que buscarlo.

### 8. El código del botón del Pase (LocalScript dentro de ComprarPase)

```lua
-- Servicios
local Players = game:GetService("Players")                        -- servicio que maneja a los jugadores
local MarketplaceService = game:GetService("MarketplaceService")  -- servicio de compras de Roblox

-- Configuracion
local ID_PASE = 000000                              -- reemplazar con el ID real de tu Pase
local MODO_PRUEBA = true                            -- true en Studio, false al publicar

-- Referencias
local jugador = Players.LocalPlayer                 -- el jugador que ve esta pantalla
local boton = script.Parent                         -- el boton que contiene este script

-- Estado
local yaComprado = false                            -- se pone en true cuando ya tiene el Pase
local disponible = false                            -- se pone en true si el Pase esta a la venta

-- Funciones
local function marcarComoComprado()
    yaComprado = true                               -- bloquea futuros clicks
    boton.Text = "Ya comprado ✓"                    -- cambia el texto del boton
end

local function mostrarPrecio()
    local exito, info = pcall(function()            -- pcall evita que un error de conexion rompa el script
        return MarketplaceService:GetProductInfoAsync(ID_PASE, Enum.InfoType.GamePass)  -- pide los datos del Pase
    end)

    if exito and info.IsForSale then                -- si la consulta funciono y esta a la venta
        disponible = true                           -- habilita la compra
        boton.Text = "Comprar por " .. info.PriceInRobux .. " Robux"  -- muestra el precio real
    else
        boton.Text = "No disponible"                -- avisa que no se puede comprar
    end
end

local function revisarSiYaLoTiene()
    local exito, tienePase = pcall(function()       -- consulta protegida con pcall
        return MarketplaceService:UserOwnsGamePassAsync(jugador.UserId, ID_PASE)  -- pregunta si ya lo compro
    end)

    if exito and tienePase then                     -- si la consulta funciono y ya lo tiene
        marcarComoComprado()                        -- deja el boton como comprado
    end
end

local function alTocarBoton()
    if yaComprado or not disponible then return end -- si ya lo tiene o no esta a la venta, no hace nada
    MarketplaceService:PromptGamePassPurchase(jugador, ID_PASE)  -- abre la ventana oficial de compra
end

local function alTerminarCompra(jugadorQueCompro, idPase, comprado)
    if jugadorQueCompro == jugador and idPase == ID_PASE and comprado then  -- fui yo, es este Pase y pague
        marcarComoComprado()                        -- actualiza el boton al instante
    end
end

-- Inicio
mostrarPrecio()                                     -- pone el precio real en el boton

if not MODO_PRUEBA then                             -- en prueba arrancamos como si no lo tuviera
    revisarSiYaLoTiene()                            -- en el juego real, revisa si ya lo compro
end

boton.Activated:Connect(alTocarBoton)               -- click con mouse o toque en celular
MarketplaceService.PromptGamePassPurchaseFinished:Connect(alTerminarCompra)  -- se cerro el dialogo de compra
```

- `GetProductInfoAsync` reemplaza a `GetProductInfo`, que quedó **deprecado** en diciembre de 2025. Si cambiás el precio en el Dashboard, el botón se actualiza solo
- `Activated` funciona con mouse **y** con toque en celular. `MouseButton1Click` solo funciona con mouse
- `Active = false` no alcanza para bloquear un botón, por eso usamos `yaComprado` con `return`
- `boton.Activated:Connect(alTocarBoton)` conecta el evento a una función **con nombre**. Es lo mismo que escribir la función adentro, pero se lee mucho mejor
- En modo prueba **no** se revisa si ya lo tiene, porque en Studio el dueño del juego siempre "tiene" sus Pases y el botón quedaría bloqueado desde el principio
- Acá el cliente confía en `comprado`, pero **solo para cambiar el texto**, nunca para dar el ítem

### 9. El script de la entrega (PaseLinterna)

1. Click derecho en **ServerScriptService** → Insert Object → **Script**
2. Lo renombrás `PaseLinterna`

```lua
-- Servicios
local Players = game:GetService("Players")                        -- servicio que maneja a los jugadores
local MarketplaceService = game:GetService("MarketplaceService")  -- servicio de compras de Roblox
local ServerStorage = game:GetService("ServerStorage")            -- donde esta guardada la Linterna

-- Configuracion
local ID_PASE = 000000                              -- reemplazar con el ID real de tu Pase
local MODO_PRUEBA = true                            -- true en Studio, false al publicar

-- Referencias
local linterna = ServerStorage:WaitForChild("Linterna")  -- el item premium que vamos a entregar

-- Funciones
local function tienePase(jugador)
    if MODO_PRUEBA then                             -- en prueba
        return false                                -- simula que todavia no lo compro
    end

    local exito, resultado = pcall(function()       -- consulta protegida con pcall
        return MarketplaceService:UserOwnsGamePassAsync(jugador.UserId, ID_PASE)  -- le pregunta a Roblox
    end)
    return exito and resultado                      -- true solo si la consulta funciono y lo tiene
end

local function compraConfirmada(jugador)
    if MODO_PRUEBA then                             -- en prueba
        return true                                 -- confia en la compra simulada de Studio
    end
    return tienePase(jugador)                       -- en el juego real, vuelve a preguntarle a Roblox
end

local function darLinterna(jugador)
    if jugador.StarterGear:FindFirstChild("Linterna") then  -- si ya se la dimos antes
        return                                      -- no la duplica
    end

    linterna:Clone().Parent = jugador.StarterGear   -- copia para cada vez que reaparece
    linterna:Clone().Parent = jugador.Backpack      -- copia para tenerla ahora mismo
end

local function alEntrarJugador(jugador)
    if tienePase(jugador) then                      -- si ya habia comprado el Pase
        darLinterna(jugador)                        -- le da la Linterna
    end
end

local function alTerminarCompra(jugador, idPase, comprado)
    if comprado and idPase == ID_PASE and compraConfirmada(jugador) then  -- pago, es este Pase y esta confirmado
        darLinterna(jugador)                        -- le da la Linterna al instante
    end
end

-- Inicio
for _, jugador in ipairs(Players:GetPlayers()) do   -- jugadores que ya estaban antes de que corra el script
    alEntrarJugador(jugador)
end

Players.PlayerAdded:Connect(alEntrarJugador)        -- jugadores que entren despues
MarketplaceService.PromptGamePassPurchaseFinished:Connect(alTerminarCompra)  -- compras durante la partida
```

- `tienePase` responde **"¿ya lo había comprado antes?"**: se usa al entrar al juego
- `compraConfirmada` responde **"¿esta compra que acaba de pasar es real?"**: se usa cuando termina el diálogo de compra
- En el juego real, aunque el evento diga `comprado`, el servidor **vuelve a preguntarle a Roblox** antes de dar nada
- El `for` del Inicio cubre un caso real: en Studio, a veces el jugador entra **antes** de que el script conecte `PlayerAdded`, y sin ese `for` nunca recibiría la Linterna

### 10. Por qué StarterGear además del Backpack

El `Backpack` (la mochila) se **vacía cada vez que el personaje reaparece**. Además, `PlayerAdded` se dispara **antes** de que aparezca el personaje, así que un ítem puesto solo en el Backpack se borraba al instante.

| Lugar | Qué pasa con lo que ponés ahí |
|---|---|
| `Backpack` | Se borra al morir o reaparecer |
| `StarterGear` | Roblox lo copia al Backpack **cada vez** que reaparecés |

Poniéndola en los dos, la tenés al instante y no la perdés al morir.

### 11. Por qué necesitamos el MODO_PRUEBA

Probar Pases en Studio es **poco confiable**, y no se arregla con código:

| Problema | Por qué pasa |
|---|---|
| El dueño del juego ya tiene el Pase sin comprarlo | Roblox le da todos los Pases de su propia experiencia |
| `UserOwnsGamePassAsync` da `true` en el cliente y `false` en el servidor | Las compras simuladas en Studio no se registran de verdad |
| Te deja "comprar" varias veces | La simulación no respeta la lógica real de "ya lo tenés" |

Por eso, en modo prueba **no le preguntamos a Roblox** si tenés el Pase. En su lugar, simulamos el flujo de un jugador nuevo:

| | `MODO_PRUEBA = true` (Studio) | `MODO_PRUEBA = false` (juego publicado) |
|---|---|---|
| Al entrar | **No** tenés la Linterna, el botón muestra el precio | Te la da si Roblox confirma que compraste |
| Al comprar | Confía en la compra de prueba y te la da | Vuelve a preguntarle a Roblox antes de darla |
| Al volver a entrar | Arrancás de nuevo sin Linterna | La tenés, porque Roblox recuerda la compra |

> ⚠️ `MODO_PRUEBA` tiene que tener el **mismo valor** en el LocalScript y en `PaseLinterna`. Antes de publicar la versión final, lo ponés en `false` en los dos.

7. Te dejás morir o reiniciás el personaje, y verificás que la Linterna **siga estando**

### 15. El código del botón del Producto (LocalScript dentro de ComprarVelocidad)

```lua
-- Servicios
local Players = game:GetService("Players")                        -- servicio que maneja a los jugadores
local MarketplaceService = game:GetService("MarketplaceService")  -- servicio de compras de Roblox

-- Configuracion
local ID_VELOCIDAD = 0000000                        -- reemplazar con el ID real del Producto

-- Referencias
local jugador = Players.LocalPlayer                 -- el jugador que ve esta pantalla
local boton = script.Parent                         -- el boton que contiene este script

-- Funciones
local function mostrarPrecio()
    local exito, info = pcall(function()            -- consulta protegida con pcall
        return MarketplaceService:GetProductInfoAsync(ID_VELOCIDAD, Enum.InfoType.Product)  -- pide los datos del Producto
    end)

    if exito then                                   -- si la consulta funciono
        boton.Text = "Velocidad +10 (" .. info.PriceInRobux .. " Robux)"  -- muestra el precio real
    else
        boton.Text = "No disponible"                -- avisa que algo fallo
    end
end

local function alTocarBoton()
    MarketplaceService:PromptProductPurchase(jugador, ID_VELOCIDAD)  -- abre la ventana oficial de compra
end

-- Inicio
mostrarPrecio()                                     -- pone el precio real en el boton
boton.Activated:Connect(alTocarBoton)               -- click con mouse o toque en celular
```

- Para Productos se usa `Enum.InfoType.Product` en vez de `GamePass`
- `PromptProductPurchase` abre el diálogo. **No devuelve nada** ni espera a que el jugador compre
- Este script es mucho más corto que el del Pase: como se puede comprar muchas veces, no hace falta `yaComprado` ni revisar si ya lo tiene

> ⚠️ Si el ID queda en `0000000`, `PromptProductPurchase` tira error porque Roblox no encuentra ningún producto con ese número.

### 16. El script de la entrega (ProductosDesarrollador)

1. Click derecho en **ServerScriptService** → Insert Object → **Script**
2. Lo renombrás `ProductosDesarrollador`

```lua
-- Servicios
local Players = game:GetService("Players")                        -- servicio que maneja a los jugadores
local MarketplaceService = game:GetService("MarketplaceService")  -- servicio de compras de Roblox

-- Configuracion
local ID_VELOCIDAD = 0000000                        -- el MISMO ID que en el LocalScript
local VELOCIDAD_EXTRA = 10                          -- cuanto suma cada compra
local DURACION = 600                                -- 600 segundos = 10 minutos
local VELOCIDAD_NORMAL = 16                         -- velocidad normal de Roblox

-- Estado
local finBoost = {}                                 -- cuando termina el boost de cada jugador

-- Funciones
local function procesarCompra(infoRecibo)
    if infoRecibo.ProductId ~= ID_VELOCIDAD then    -- si no es este Producto
        return Enum.ProductPurchaseDecision.NotProcessedYet  -- no lo procesa
    end

    local jugador = Players:GetPlayerByUserId(infoRecibo.PlayerId)  -- busca al jugador que compro
    local humanoid = jugador and jugador.Character and jugador.Character:FindFirstChild("Humanoid")  -- su Humanoid
    if not humanoid then                            -- si no esta o no aparecio
        return Enum.ProductPurchaseDecision.NotProcessedYet  -- Roblox reintenta mas tarde
    end

    humanoid.WalkSpeed = humanoid.WalkSpeed + VELOCIDAD_EXTRA  -- suma 10 de velocidad

    local ahora = os.clock()                        -- el tiempo actual
    local fin = (finBoost[jugador] or ahora) + DURACION  -- le suma 10 minutos a lo que le quedaba
    finBoost[jugador] = fin                         -- guarda el nuevo final

    task.delay(fin - ahora, function()              -- espera hasta el final sin frenar el script
        if finBoost[jugador] == fin then            -- si no compro otro despues de este
            finBoost[jugador] = nil                 -- borra el boost
            humanoid.WalkSpeed = VELOCIDAD_NORMAL   -- vuelve a la velocidad normal
        end
    end)

    return Enum.ProductPurchaseDecision.PurchaseGranted  -- le confirma a Roblox que ya entregamos
end

-- Inicio
MarketplaceService.ProcessReceipt = procesarCompra  -- Roblox llama a esta funcion con cada compra
```

- `ProcessReceipt` es la función que Roblox llama **automáticamente** cada vez que se confirma un pago de un Producto del desarrollador
- `infoRecibo.ProductId` indica qué se compró e `infoRecibo.PlayerId` quién lo compró
- `PurchaseGranted` le confirma a Roblox que ya entregaste. Si devolvés `NotProcessedYet`, Roblox **reintenta más tarde**, así nadie pierde lo que pagó
- `task.delay` programa la vuelta a la velocidad normal **sin frenar** `procesarCompra`, que tiene que devolver `PurchaseGranted` enseguida

### 17. Cómo funciona el tiempo que se suma

`finBoost` guarda, para cada jugador, **en qué momento termina** su boost.

- `finBoost[jugador] or ahora`: si ya tenía un boost, parte de su final; si no tenía, parte de ahora
- Le suma `DURACION` (10 minutos)
- Cada `task.delay` revisa si sigue siendo el final más reciente. Si el jugador compró otra vez, `finBoost[jugador]` cambió, y ese delay viejo no hace nada

**Ejemplo:**

| Momento | Qué pasa | Velocidad | Termina a los |
|---|---|---|---|
| Minuto 0 | Compra 1 | 26 | 10 minutos |
| Minuto 3 | Compra 2 | 36 | 20 minutos (le quedaban 7 + 10) |
| Minuto 10 | El primer delay ve que no es el más nuevo, no hace nada | 36 | 20 minutos |
| Minuto 20 | Se termina el boost | 16 | — |

> 💡 Si el jugador muere, el personaje nuevo arranca con velocidad normal. Para una clase sencilla está bien así.

### 18. Un solo ProcessReceipt en todo el juego

> ⚠️ **Solo puede haber un `ProcessReceipt` en todo el juego.** Si lo escribís en dos scripts, el segundo pisa al primero y el primero deja de funcionar.

Por eso el script se llama `ProductosDesarrollador` (en plural): si mañana agregás otro Producto, como "Curación completa", va **en este mismo script**, agregando otro `if` para su ID. No se crea un script nuevo.

> ⚠️ **Nunca** uses `PromptProductPurchaseFinished` para entregar un Producto. Ese evento solo avisa que se cerró el diálogo, no que el pago se procesó.

> 💡 Roblox tiene una función más nueva llamada `BindReceiptHandler`, pensada para reemplazar a `ProcessReceipt`. En nuestras pruebas en Studio **no recibió las compras de prueba**, así que usamos `ProcessReceipt`, que es la forma probada y sigue siendo válida.

> 💡 Un boost temporal no hace falta guardarlo. Pero si vendés algo que se **acumula** (100 monedas, 5 vidas extra), Roblox **no** recuerda cuántas tiene cada jugador: eso se guarda con DataStore (Clase 31).

### 21. Extra: varios Pases en un solo script

Si querés vender varios Pases, en vez de hacer un script por cada uno, se usa una **tabla** (Clase 21) donde cada ID tiene el nombre del ítem que entrega. Este script **reemplaza** a `PaseLinterna`:

```lua
-- Servicios
local Players = game:GetService("Players")                        -- servicio que maneja a los jugadores
local MarketplaceService = game:GetService("MarketplaceService")  -- servicio de compras de Roblox
local ServerStorage = game:GetService("ServerStorage")            -- donde estan guardados los items

-- Configuracion
local MODO_PRUEBA = true                            -- true en Studio, false al publicar

local PASES = {                                     -- tabla: ID del Pase -> nombre del item
    [000000] = "Linterna",                          -- este Pase da la Linterna
    [222222] = "EspadaDorada",                      -- este Pase da la EspadaDorada
}

-- Funciones
local function tienePase(jugador, idPase)
    if MODO_PRUEBA then                             -- en prueba
        return false                                -- simula que todavia no lo compro
    end

    local exito, resultado = pcall(function()       -- consulta protegida con pcall
        return MarketplaceService:UserOwnsGamePassAsync(jugador.UserId, idPase)  -- le pregunta a Roblox
    end)
    return exito and resultado                      -- true solo si funciono y lo tiene
end

local function compraConfirmada(jugador, idPase)
    if MODO_PRUEBA then                             -- en prueba
        return true                                 -- confia en la compra simulada de Studio
    end
    return tienePase(jugador, idPase)               -- en el juego real, vuelve a preguntarle a Roblox
end

local function darItem(jugador, nombreItem)
    if jugador.StarterGear:FindFirstChild(nombreItem) then  -- si ya lo tiene
        return                                      -- no lo duplica
    end

    local item = ServerStorage:WaitForChild(nombreItem)  -- busca el item por su nombre
    item:Clone().Parent = jugador.StarterGear       -- copia para cada respawn
    item:Clone().Parent = jugador.Backpack          -- copia para ahora mismo
end

local function alEntrarJugador(jugador)
    for idPase, nombreItem in pairs(PASES) do       -- recorre todos los Pases de la tabla
        if tienePase(jugador, idPase) then          -- si tiene este Pase
            darItem(jugador, nombreItem)            -- le da su item
        end
    end
end

local function alTerminarCompra(jugador, idPase, comprado)
    local nombreItem = PASES[idPase]                -- busca que item corresponde a ese Pase
    if comprado and nombreItem and compraConfirmada(jugador, idPase) then  -- pago, existe en la tabla y esta confirmado
        darItem(jugador, nombreItem)                -- le da el item
    end
end

-- Inicio
for _, jugador in ipairs(Players:GetPlayers()) do   -- jugadores que ya estaban
    alEntrarJugador(jugador)
end

Players.PlayerAdded:Connect(alEntrarJugador)        -- jugadores que entren despues
MarketplaceService.PromptGamePassPurchaseFinished:Connect(alTerminarCompra)  -- compras durante la partida
```

- Si el ID no está en la tabla, `PASES[idPase]` da `nil` y no entrega nada
- Agregar un Pase nuevo es **una sola línea** en la tabla, y el ítem tiene que existir en ServerStorage con ese mismo nombre
- Cada botón de Pase sigue teniendo su propio LocalScript, igual al del paso 8 pero con su ID
